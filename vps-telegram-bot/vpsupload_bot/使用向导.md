## 📁 VPS 交互式文件管理器与媒体处理机器人 (vpsupload_bot) 使用向导

欢迎使用 vpsupload_bot。本项目是一个基于 Python 异步架构开发的 Telegram 机器人，旨在将您的 Telegram 客户端转变为一个可视化的 VPS 远程文件管理器，并集成了基于 FFmpeg 的视频处理（转码、拼接、推流）与 YouTube 断点续传上传功能。

本向导将为您提供从环境准备、API 授权、参数配置到自动化部署及核心功能使用的全方位指导。

### 🛠️ 1. 环境准备与系统依赖

> 在开始部署之前，请确保您的 VPS 满足以下基础系统环境要求。
>
> #### 1.1 操作系统与核心组件
>
> 系统需要安装 Python 3.8+ 以及 FFmpeg / FFprobe（用于读取媒体时长和转码推流）。
>
> ##### Ubuntu / Debian 系统安装命令：
>
> ```Bash
> sudo apt update
> sudo apt install python3 python3-pip python3-venv ffmpeg -y
> ```
>
> ##### CentOS / RHEL / Rocky Linux 系统安装命令：
>
> 由于 FFmpeg 在某些红帽系源中不自带，需要先启用 EPEL 存储库：
>
> ```Bash
> sudo dnf install epel-release -y
> sudo dnf makecache
> sudo dnf install python3 python3-pip ffmpeg -y
> ```
>
> #### 1.2 Python 依赖库
>
> 机器人运行依赖于 python-telegram-bot（异步版本）和 Google API 客户端。核心依赖包如下：
>
> ```
> python-telegram-bot
> ```
>
> ```
> google-api-python-client
> ```
>
> ```
> google-auth-httplib2
> ```
>
> ```
> google-auth-oauthlib
> ```

### 🔑 2. YouTube API 授权初始化（关键步骤）

> 由于 YouTube 上传功能采用了安全的 OAuth 2.0 认证机制，因此无法直接在 VPS 上通过账号密码登录。需要提前在本地个人电脑上完成人工授权，并生成包含 Refresh Token 的 token.json 凭据文件。
>
> #### 详细步骤：
>
> ##### 1.创建 Google Cloud 项目：
>
> 登录 Google Cloud Console。
>
> 创建一个新项目，在 API 库中搜索并启用 YouTube Data API v3。
>
> ##### 2.配置 OAuth 同意屏幕：
>
> 进入“OAuth 同意屏幕”设置，应用类型选择 测试版 (External)。
>
> 添加您的 Google 账号作为测试用户（非常重要，否则无法通过授权）。
>
> ##### 3.创建凭据：
>
> 进入“凭据”页面，点击“创建凭据” -> OAuth 客户端 ID。
>
> 应用类型选择 桌面应用 (Desktop App)，名称自定义，点击创建。
>
> ##### 4.下载凭据文件：
>
> 在凭据列表中找到刚创建的客户端，点击右侧的下载按钮，获取 JSON 文件。
>
> 将该文件重命名为 `client_secrets.json`。
>
> ##### 5.在本地运行授权脚本：
>
> 将 `client_secrets.json` 与项目附带的 `get josn.py` 文件置于本地个人电脑的同一个文件夹内。
>
> 在本地终端或命令行中执行：
>
> ```Bash
> python "get josn.py"
> ```
>
> 此时本地电脑会自动弹出浏览器，要求您登录 Google 账号并授予 YouTube 上传权限。
>
> 授权完成后，脚本会在同级目录下自动生成一个名为 token.json 的文件。
>
> ##### 6.上传凭据至 VPS：
>
> 使用 SFTP、SCP 或宝塔面板等工具，将生成的 `token.json` 传送到 VPS 上机器人所在的 `vpsupload_bot` 工作目录中。

### ⚙️ 3. 机器人参数配置

> 在启动机器人之前，必须使用文本编辑器（如 `nano` 或 `vim`）打开 `bot_main.py`，修改` == 配置区域 ==` 下的硬编码参数，以确保安全性与功能正常。
>
> ```Python
>
> # ================= 配置区域 =================
>
> BOT_TOKEN = "8672414310:**\*\***\*\*\*\***\*\***" # 替换为从 @BotFather 获取的真实 Bot Token
> ADMIN_ID = 123456789 # 替换为您的 Telegram 用户数字 ID（纯数字，防范越权）
> BASE_DIR = "/storage512/bilivego/download" # 修改为机器人在 VPS 上浏览和操作的基础根目录
> RTMP_URL = "rtmp://a.rtmp.youtube.com/live2/\***\*-\*\***-\***\*-\*\***" # 配置默认推流目标地址
>
> # ===========================================
> ```
>
> ##### ⚠️ 安全提示： 请务必正确填写 ADMIN_ID。机器人内部设置了严格的权限校验函数 is_admin()，非管理员的任何指令与回调请求都将被直接阻断。

### 🚀 4. 部署与后台常驻运行

> 本项目提供了 自动化脚本部署 与 手动常驻部署 两种方式。
>
> #### 方案 A：使用一键自动化脚本（推荐）
>
> 项目文件夹内包含 install_bot.sh 部署脚本，它会自动完成目录创建、依赖检查、虚拟环境初始化、参数配置注入以及 Systemd 服务注册。
>
> 以 root 用户身份运行脚本：
>
> ```Bash
> sudo bash install_bot.sh
> ```
>
> 根据提示输入您的 `BOT_TOKEN` 和 `ADMIN_ID`。
>
> 脚本会自动进行阻塞式检测，提示您将本地生成的 `token.json` 上传到 `/root/video_bot` 目录。
>
> 传输完成后按回车，脚本会将其注册为系统守护进程服务 `videobot.service`。
>
> 服务管理命令：
> 查看实时日志： `journalctl -u videobot -f`
>
> 启动服务： `systemctl start videobot`
>
> 停止服务： `systemctl stop videobot`
>
> 重启服务： `systemctl restart videobot`
>
> #### 方案 B：手动后台常驻启动（Nohup 模式）
>
> 如果您选择不使用 Systemd 服务，也可以直接在虚拟环境或系统环境中使用 nohup 维持后台运行：
>
> ```Bash
> nohup python3 bot_main.py > bot.log 2>&1 &
> ```
>
> 查看日志： `tail -f bot.log`
>
> 停止机器人： 先使用 `ps -ef | grep bot_main.py` 查出进程 PID，然后执行`kill PID`。

### 🎮 5. 核心功能与交互指令

> 机器人启动后，在 Telegram 聊天框中即可进行可视化交互。
>
> #### 5.1 基础控制指令
>
> `/start`：唤醒机器人，初始化路径状态，并在控制台展示主菜单面板。
>
> `/stop`：全局强力中断指令。无论当前是在进行异步 FFmpeg 推流、批量转码，还是 YouTube 分片上传，发送 /stop 将会下发取消信号（cancel_flag = True）并强制杀掉底层 ffmpeg 进程，安全终止当前任务。
>
> #### 5.2 目录浏览与文件穿梭
>
> 无限深度下钻：取消了旧版本的单级目录限制。系统会自动扫描当前目录，将所有子文件夹冠以 📁 标识并优先排列在顶部。点击 📁 即可进入下级目录。
>
> 平滑回溯：若当前不在 BASE_DIR 根目录，菜单底部会动态生成一个 ⬆️ 返回上一级目录 按钮，点击即可一键回退。
>
> 智能路径映射：为节省屏幕空间，顶部路径中的 BASE_DIR 会被精简映射为 🏠 根目录 标识（如 📂 路径: 🏠/videos/2026）。
>
> #### 5.3 单选操作模式
>
> 适用于“浏览与查看详情”、“📡 RTMP 单路推流”以及“☁️ YouTube 上传”功能。在这些模式下，直接点击对应文件即可触发：
>
> ###### 📂 浏览远程文件 (查看详情)：
>
> 点击视频文件后，系统会触发弹窗提示，展示文件的精确信息：包含文件名、智能转换的大小（小于 1GB 显示 MB，大于显示 GB）、利用 ffprobe 实时探测的视频精确时长（hh:mm:ss）以及文件的最后修改时间。
>
> ###### 📡 RTMP 单路推流：
>
> 采用异步非阻塞方式调用 FFmpeg。命令参数为 -re -i [file_path] -c copy -f flv RTMP_URL（无损流拷贝，极低 CPU 占用）。
>
> 聊天界面会实时刷新滚动进度条（████░░░░）与当前推流时间进度。
>
> ###### ☁️ YouTube 上传：
>
> 采用 YouTube 官方可恢复的断点续传机制（Resumable Upload），设置分片块大小为 10MB。
>
> 默认上传属性：隐私状态设为 Private（私享），且开启 ytAgeRestricted（18+ 年龄限制），确保视频资产在云端的隐私与安全。
>
> 界面实时展示上传百分比进度条。
>
> #### 5.4 多选批量操作模式
>
> 适用于“✂️ 智能视频合并”、“🔄 批量转码 MP4”以及“🗑️ 批量删除文件”。进入相应模式后：
>
> 点击文件可以进行勾选或取消勾选，文件名左侧状态会在 ⬜️（未选）与 ✅（已选）之间切换。支持跨页翻页勾选。
>
> 勾选完成后，底部会动态出现 ▶️ 确认执行 (X 个文件) 按钮。
>
> ###### ✂️ 智能视频合并 (Concat)：
>
> 就近工作流：合并所需的临时队列文件 concat_list.txt 以及最终产物，都将自动在当前所在目录下进行 I/O 读写，彻底杜绝了跨目录合并导致的路径溢出。
>
> 智能命名 (Smart Rename)：系统会自动提取队列中第一个文件的名称，利用正则表达式高效捕获形如 YYYY-MM-DD 的日期。如果带有特定格式，会自动剥离前缀，拼装为 [日期]\_[标题部分].[后缀]；若未匹配到日期，则自动以当前系统日期命名（例如 Merged_20260520_merged.mp4），并采用 -c copy 执行极速无损无缝拼接。
>
> ###### 🔄 批量转码 MP4：
>
> 专门用于处理格式兼容性。调用 FFmpeg 将非 MP4 视频（如 .mkv, .flv, .ts）重封装。
>
> 执行命令：`ffmpeg -y -i [input] -c copy -movflags +faststart [output.mp4]`。其中 +faststart 会将视频的元数据（moov atom）移至文件头部，使转码后的视频支持网络秒开与边下边播。
>
> ###### 🗑️ 批量删除文件：
>
> 勾选多个文件后，一键执行物理删除，并在完成后弹窗提示成功清理的文件总数，是快捷释放 VPS 磁盘空间的利器。

### ❌ 7. 常见问题与故障排查 (FAQ)

> #### Q1: 点击按钮提示“❌ 缺少 token.json”怎么办？
>
> `A: 说明您没有将本地生成的 token.json 成功上传到 VPS 上运行脚本的同级目录。请检查路径，如果使用的是 Systemd 脚本部署，该文件必须存放在 /root/video_bot/token.json。`
>
> #### Q2: 视频推流或转码时，进度条一直停留在“获取进度中...”或提示“无法获取视频时长”？
>
> `A: 请确保您的 VPS 系统中已经成功安装了 ffmpeg 和 ffprobe。可以在 SSH 终端执行 ffmpeg -version 和 ffprobe -version 确认。如果视频文件本身损坏或属于纯无损原始流，可能无法探测到时长。`
>
> #### Q3: 为什么多选模式下，点击文件夹会变成勾选而不是进入？
>
> `A: 在本系统中，文件夹不支持作为多选操作的对象。无论处于何种多选模式（合并/转码/删除），点击 📁 标识的文件夹都依然是“进入该文件夹”的下钻逻辑；只有点击常规视频文件时，才会触发 ⬜️ / ✅ 的状态切换。`
>
> #### Q4: 发送 /start 指令后机器人没有任何反应？
>
> `A: 1. 请检查机器人的后台进程或 Systemd 服务是否正常运行（使用 systemctl status videobot）。`  
> `2. 请检查 bot_main.py 中的 ADMIN_ID 是否与您真实的 Telegram 账号数字 ID 绝对一致。如果不一致，机器人的权限防御机制会直接静默忽略您的请求。`
