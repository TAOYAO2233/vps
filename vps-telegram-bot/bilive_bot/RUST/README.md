# Rust bot 录制详情

点击任务进入详情面板，通过 `GET /api/lives/{id}` 获取监控状态、录制状态、实际探测的分辨率/编码/码率/帧率、当前文件大小与路径、开播及录制开始时间。

- **刷新详情**：编辑当前消息，不自动定时刷新。
- **查看流 URL / Headers**：管理员可查看独立分页信息，保留服务端 Headers 脱敏结果。每次翻页重新读取 API，录制切流时内容可能变化。
- **返回列表**：同时恢复列表标题和按钮。
- **停止监控**：保留原来的 `stop` 行为，停止监控及相关录制，不是独立暂停录制。

## 显示规则

实际参数使用 `actual_*` 字段；探测等待时显示“探测中”，缺失时显示“暂无数据”。平台声明分辨率单独标明，不代替实际探测值。视频码率字段本身单位为 kbps，不重复换算。时间保留 Bililive-go 服务器原始时间，不推断时区。

文件大小使用二进制单位 KiB/MiB/GiB。下载速度使用同一文件两次详情读取之间的文件大小差估算，标注采样时间；首次读取显示“采样中”。录制开始时间或文件路径变化、文件大小回退、停止录制、手动控制后会重新采样。采样超过 10 分钟失效，重启 bot 后也需重新采样。该值是文件写入平均速度，并非网络接口瞬时速度。

消息使用纯文本，标题、文件路径及 Headers 不会被解释为 Telegram Markdown。长详情字段显示省略号；流信息按 UTF-16 长度分页，避免超出 Telegram 消息限制。API 失败与空列表分开显示，配置同步失败单独反馈，避免误报操作成功。

## 配置

依赖见 `Cargo.toml`；已移除不再需要的 `once_cell`。在工作目录 `.env` 中配置 `TELOXIDE_TOKEN`、`API_BASE_URL`、`ADMIN_IDS`、`POLLING_INTERVAL`、`RUST_LOG`。启动时先加载 `.env` 再初始化日志和 Telegram Bot。

## 人工验收清单

请在自行构建运行后验证：

1. 管理员打开列表、进入录制中的任务，核对 WebUI 的实际参数、文件及时间。非管理员不能读取详情或流信息。
2. 间隔数秒刷新两次，确认估算速度出现；连续快速点击不会报“消息未修改”错误。
3. 停止录制、准备录制、探测未完成、字段缺失时显示正确；分段后重新采样。
4. URL/Headers 较长时可翻页并返回详情；特殊字符和中文路径不导致消息解析失败。
5. 返回列表后标题和按钮恢复；API 超时/断开时显示读取失败而非空列表。
6. 添加/删除/控制失败或配置同步失败时，不能显示完全成功。

本次未执行编译、构建、运行项目或部署；这些验收尚未实测。


## 工程结构与职责

```text
src/
  main.rs          启动、依赖注入、后台任务生命周期
  config.rs        环境变量读取、配置校验、管理员判定
  error.rs         类型化 API 错误及安全的用户提示
  models.rs        HTTP 请求/响应模型和统计数值兼容转换
  api.rs           可复用 HTTP 客户端、任务操作、配置同步
  state.rs         应用实例拥有的配置、客户端和异步采样锁
  callbacks.rs     回调协议解析及允许的控制动作
  handlers.rs      Telegram 权限、消息分发、编辑与操作流程
  monitor.rs       后台录制状态转换检测与通知
  speed.rs         有时效的文件采样与速度计算，不依赖 Telegram/UI
  ui/
    panels.rs      查询并组装列表、任务详情、流信息页面
    text.rs        纯文本格式、UTF-16 截断与分页
```

`main.rs` 只负责装配。`Arc<AppState>` 通过 Dispatcher 依赖注入传给处理器，避免全局可变单例。API 层不访问 Telegram 或采样状态；速度模块返回 `SpeedEstimate`，由 UI 决定显示文字。采样锁仅保护内存计算，不跨 HTTP/Telegram 请求持有。`recorder_status` 有意保留 JSON 扩展字段，以兼容不同录制器及上游可选统计字段。

修改交互逻辑从 `handlers.rs` 和 `callbacks.rs` 入手，新增 API 从 `models.rs` 和 `api.rs` 入手，调整显示从 `ui/` 入手。新增模块默认使用 `pub(crate)`，避免不必要的公开接口。

## 配置校验与兼容性

`.env.example` 提供变量模板，不含真实凭据；`.gitignore` 排除本地凭据和 `target/`。启动时要求非空 Token、至少一个合法正整数管理员 ID、非零轮询间隔以及有效 HTTP(S) API 基础地址；管理员 ID 自动去重。错误配置不再静默回退。日志初始化前加载 `.env`，配置结构不实现 `Debug`，避免意外打印 Token。

既有 `refresh_main`、`view_*`、`stream_*`、`op_*`、`conf_del_*` 回调继续有效，含下划线的任务 ID 可保留完整；ID 限制为字母、数字、连字符和下划线。保持现有启动时发现录制中任务即发送提醒的行为。轮询失败不清空状态，成功获取列表后清理已删除任务快照。
