# VPS Media Control Bot 使用指南

面向 VPS 部署的 Telegram 媒体控制机器人：远程浏览/删除文件，执行 RTMP 推流、视频智能合并、批量转码 MP4 与 YouTube 批量上传。

> 运行环境：Linux / macOS（需 FFmpeg）；Windows 亦可运行，但生产部署建议 Linux。

---

## 1. 快速开始（5 步）

```bash
# 1) 安装 Rust 与 FFmpeg（Debian / Ubuntu）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
sudo apt update && sudo apt install -y ffmpeg

# 2) 获取代码并编译
cd /opt && git clone <你的仓库地址> media-control-bot && cd media-control-bot
cargo build --release          # 产物：target/release/media-control-bot

# 3) 准备配置
cp .env.example .env && vim .env        # 至少填写 BOT_TOKEN、ADMIN_ID、BASE_DIR
chmod 600 .env

# 4)（可选）准备 YouTube 凭证
cp /path/to/token.json ./token.json && chmod 600 ./token.json

# 5) 前台试运行（确认无误后再交给 systemd）
./target/release/media-control-bot
```

启动后在 Telegram 里给机器人发送 `/start`。

## 3. 配置说明（`.env`）

程序启动时会从**当前工作目录**读取 `.env`（不存在则仅使用进程环境变量），随后做合法性校验，校验失败会直接退出并打印原因。

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `BOT_TOKEN` | 是 | — | Telegram Bot Token，不能为空 |
| `ADMIN_ID` | 是 | — | 唯一管理员数字 ID，不能为 0；非管理员操作会被静默忽略 |
| `BASE_DIR` | 是 | `/storage512/bilivego/download` | 媒体根目录；所有文件操作都被限制在此目录内（防目录穿越） |
| `RTMP_URL` | 否 | 空 | 推流地址，形如 `rtmp://host/app/streamkey`；为空时推流功能会提示未配置 |
| `ITEMS_PER_PAGE` | 否 | `8` | 文件选择器每页条目数，必须 > 0 |
| `TOKEN_FILE` | 否 | `./token.json` | YouTube OAuth2 凭证路径（相对路径基于工作目录） |
| `YOUTUBE_MAX_CONCURRENT_UPLOADS` | 否 | `2` | YouTube 同时上传数，必须 > 0；其余任务排队等待 |
| `YOUTUBE_UPLOAD_CHUNK_MB` | 否 | `10` | **预留项**：分块由依赖库内部控制，当前不影响实际分块大小 |
| `MERGE_MIN_DURATION_RATIO` | 否 | `0.95` | 合并结果时长下限（相对输入总时长），取值 0.0~1.0 |
| `MERGE_MIN_SIZE_RATIO` | 否 | `0.80` | 合并结果体积下限（相对输入总大小），取值 0.0~1.0 |
| `LOG_FORMAT` | 否 | `pretty` | 仅支持 `pretty`（彩色可读）或 `json`（结构化，适合日志采集） |
| `RUST_LOG` | 否 | `media_control_bot=info,teloxide=warn,hyper=warn` | 日志级别过滤（tracing 语法） |

注意：

- `BASE_DIR` 必须真实存在且可读，否则启动时会告警并退化为未规范化路径，选择器随后会提示“目录不存在”。
- 只允许 `.mp4`、`.mkv`、`.flv`、`.ts` 四种扩展名出现在文件列表中，其他文件既看不到也无法操作。
- `.env` 与 `token.json` 属敏感文件，请务必 `chmod 600`，且不要提交到 Git。

## 4. YouTube 凭证（`token.json`）

上传使用 OAuth2 的 `authorized_user` 凭证，所需 scope 为 `https://www.googleapis.com/auth/youtube.upload`。文件内容形如：

```json
{
  "client_id": "xxxxxxxx.apps.googleusercontent.com",
  "client_secret": "xxxxxxxx",
  "refresh_token": "xxxxxxxx",
  "token_uri": "https://oauth2.googleapis.com/token",
  "scopes": ["https://www.googleapis.com/auth/youtube.upload"],
  "type": "authorized_user"
}
```

**方式一（最快，OAuth 2.0 Playground）**

1. 打开 <https://developers.google.com/oauthplayground/>
2. 右上角齿轮 → 勾选 *Use your own OAuth credentials*，填入你的 `client_id` / `client_secret`
3. 左侧选择 *YouTube Data API v3* → `https://www.googleapis.com/auth/youtube.upload` → Authorize APIs
4. 用管理员账号登录并授权 → 第二步点 *Exchange authorization code for tokens*
5. 把得到的 `refresh_token` 与你在 Google Cloud 控制台创建的自有凭证信息拼成上面的 `token.json`

**方式二（脚本生成）**

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install google-auth-oauthlib
python - <<'PY'
from google_auth_oauthlib.flow import InstalledAppFlow
flow = InstalledAppFlow.from_client_secrets_file(
    "client_secret.json", ["https://www.googleapis.com/auth/youtube.upload"])
creds = flow.run_console()          # 按提示在浏览器打开授权链接
open("token.json", "w").write(creds.to_json())
PY
chmod 600 token.json
```

上传行为说明：视频一律以 **私享（private）** 上传，分类为 People & Blogs，标题取**文件名（含扩展名）**并截断到 95 字符，描述为空。上传完成后消息里会给出观看链接与 Studio 编辑链接。

## 5. 后台运行（systemd）

`/etc/systemd/system/media-control-bot.service`：

```ini
[Unit]
Description=VPS Media Control Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=media
# 必须是包含 .env 与 token.json 的目录，否则读不到配置
WorkingDirectory=/opt/media-control-bot
ExecStart=/opt/media-control-bot/target/release/media-control-bot
Environment=RUST_LOG=media_control_bot=info,teloxide=warn
Environment=PATH=/usr/local/bin:/usr/bin:/bin
Restart=on-failure
RestartSec=5
# 可选：限制资源，避免转码把机器打满
CPUWeight=50

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now media-control-bot
sudo systemctl status media-control-bot
sudo journalctl -u media-control-bot -f
```

停止与优雅停机：

- `sudo systemctl stop media-control-bot` 发送的是 **SIGTERM**，进程会立即退出，正在运行的 FFmpeg 子进程由 `kill_on_drop` 兜底终止；
- 若希望走完整优雅停机流程（先通知任务取消、等待 300ms 再退出），可在前台运行时按 **Ctrl+C（SIGINT）**，或在 unit 中增加 `KillSignal=SIGINT`；
- 无论哪种方式，重新启动前建议确认没有残留进程：`pgrep -af ffmpeg`。

## 6. 命令与界面

| 命令 | 作用 |
| --- | --- |
| `/start` | 显示主控面板（根目录、当前独占任务、上传/排队数量） |
| `/stop` | 停止当前独占任务，并把所有 YouTube 上传标记为取消 |
| `/uploads` | 查看 YouTube 上传任务列表（文件名、状态、进度、已运行时间） |

主菜单按钮：

`📂 浏览远程文件` · `📡 RTMP 单路推流` · `☁️ YouTube 上传` · `✂️ 智能视频合并` · `🔄 批量转码 MP4` · `🗑️ 批量删除文件`

文件选择器通用操作：`📁 目录` 进入下一级、`⬆️ 返回上一级目录`、`⬅️/➡️ 翻页`、`🔙 返回主菜单`；多选模式下点击条目切换 `⬜️/✅`，选够后点 `▶️ 确认执行 (N 个文件)`。

### 6.1 浏览远程文件

单选模式，点击文件即以弹窗展示 **文件名、大小、时长（ffprobe）、修改时间**。中文长文件名导致内容超过 Telegram 弹窗上限时，会自动改为在消息里展示详情。

### 6.2 RTMP 单路推流

- 单选模式，点击文件立即开始推流；
- 使用 `ffmpeg -re -i <文件> -c copy -f flv <RTMP_URL>`，**不转码**；
- 进度条每约 2 秒（且进度变化 ≥ 1%）刷新一次，显示 `已推流秒数 / 总秒数`；
- 仅支持 FLV 可承载的编码（推荐 H.264 + AAC）。HEVC/AV1 等需先用其他工具转码，否则 FFmpeg 会直接报错退出。

### 6.3 YouTube 上传

- 多选模式，可一次选多个文件，逐个创建上传任务；
- 受 `YOUTUBE_MAX_CONCURRENT_UPLOADS` 限制并发，其余任务显示“排队中”；
- 进度条每约 2 秒刷新一次，`/uploads` 可随时查看；
- 每个文件会单独发一条进度消息，任务完成/失败/取消时该消息就地更新为最终结果。

### 6.4 智能视频合并

- 多选至少 2 个文件，输出统一为 `.mp4`，文件名由第一个文件智能生成（提取日期时间 + 标题），同名自动追加 `_1`、`_2`；
- 两阶段策略：先尝试**极速直连拼接**（`-f concat -c copy`）；若校验不通过，自动将各片段无损封装为 `.ts` 后再拼接（解决 FLV/MKV 时间轴不连续问题）；
- 校验采用**时长 + 体积双指标**：输出时长 ≥ 输入总时长 × `MERGE_MIN_DURATION_RATIO`，输出体积 ≥ 输入总大小 × `MERGE_MIN_SIZE_RATIO`；
- 若任一片段无法无损封装为 TS，会提示“建议先单文件转码后再试”。

### 6.5 批量转码 MP4

- 多选模式，逐个执行 `ffmpeg -y -i <源> -c copy -movflags +faststart <同名>.mp4`（**仅重新封装，不重编码**）；
- 输出与原文件同目录，同名时自动追加 `_1`、`_2`，源文件保留；
- 完成后汇总“成功转换 X/Y 个文件”；失败的产物会被删除，不会留下半成品。

### 6.6 批量删除文件

- 多选模式 → 进入**二次确认**页（预览前 12 个文件名）→ 点 `✅ 确认删除` 才真正执行，`取消` 返回选择器；
- 只删除文件，不删除目录；删除不可恢复。

## 7. 运行规则与限制

- **独占任务互斥**：推流、合并、转码、删除同属“独占任务”，同一时刻只能有一个在跑；已有独占任务时再次启动会提示“已有任务正在运行”，先 `/stop` 或等待完成。
- **上传与独占任务互斥**：只要存在上传/排队的 YouTube 任务，独占任务会被拒绝；反之独占任务运行期间也无法新建上传，避免边上传边改动同一文件。
- **取消生效时机**：推流/转码在约 0.5 秒内响应 `/stop`；合并/TS 封装在约 0.2 秒内响应；YouTube 上传在当前分块返回后停止。
- **进度刷新节流**：所有进度消息最多每约 2 秒（且变化 ≥ 1%）更新一次，避免触发 Telegram 限流。
- **路径安全**：所有路径都经 BASE_DIR 边界校验，符号链接指向目录外会被拒绝。
- **权限**：只有 `ADMIN_ID` 可操作，其他用户的操作被静默忽略。
- **单实例**：同一 Token 只应运行一个实例，否则 Telegram 长轮询会互相抢占更新。

## 8. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 启动即退出，提示 `BOT_TOKEN is not set` | `.env` 未找到或工作目录不对。确认 `WorkingDirectory` 指向 `.env` 所在目录，或在 systemd 里显式写 `Environment=` |
| 提示 `Configuration error: ... must be between 0.0 and 1.0` | 比例类配置越界，按第 3 节取值修正 |
| 目录里明明有文件却看不到 | 只显示 `.mp4/.mkv/.flv/.ts`，且必须位于 `BASE_DIR` 内；确认文件权限对运行用户可读 |
| 点推流后立刻失败 | 未配置 `RTMP_URL`，或源文件编码不适合 FLV 直播（HEVC/AV1）。先转码为 H.264 + AAC |
| 合并提示“未达到校验阈值” | 片段编码参数不一致导致拼接截断。按提示先对每个片段做一次转码（`🔄 批量转码 MP4` 只能重封装，若仍失败需用 FFmpeg 重新编码） |
| 上传报 `Failed to read YouTube token file` | `TOKEN_FILE` 路径不对，或 token.json 内容/格式不正确 |
| 上传报权限/配额错误 | token 的 scope 不是 `youtube.upload`，或该 Google 账号的 API 配额用尽 |
| 进度条长时间不动 | 推流/转码进度依赖 FFmpeg 的 `time=` 输出，请确认使用的是官方 FFmpeg（不要用精简版）。程序已同时兼容 `\r` 与 `\n` 分隔的统计行 |
| `/stop` 后提示仍有任务 | YouTube 上传需等当前分块返回才会退出，稍等片刻或查看 `/uploads` |
| 机器卡顿 | 转码/合并为 CPU 与磁盘密集型操作，可用 systemd 的 `CPUWeight`、`IOWeight` 限流 |

自检步骤：

```bash
# 1) 确认 ffmpeg 能被服务进程找到
sudo -u media env PATH=/usr/local/bin:/usr/bin:/bin ffmpeg -version

# 2) 确认配置校验通过（会打印加载到的 .env 路径与基础目录）
cd /opt/media-control-bot && ./target/release/media-control-bot

# 3) 查看日志
sudo journalctl -u media-control-bot -n 200 --no-pager
```

## 9. 日志与运维

- 日志默认输出到标准输出（由 systemd/journald 收集）；`LOG_FORMAT=json` 可切换为结构化日志，便于接入 Loki/ELK。
- 需要精确定位问题时临时调高级别：`RUST_LOG=media_control_bot=debug,teloxide=warn`。
- 关键日志包含：启动参数（根目录、上传并发、chunk 提示）、任务开始/结束/取消/失败、FFmpeg 进程 PID、每次上传的 `video_id`。
- 升级流程：`git pull && cargo build --release && sudo systemctl restart media-control-bot`。
- 开发/自检命令：`cargo fmt --check`、`cargo clippy --all-targets --all-features`、`cargo test`。
