# VPS Media Control Bot 使用指南

面向 Linux VPS 部署的 Telegram 媒体控制机器人：安全浏览/删除录播文件，执行 RTMP 无损推流、多阶段视频无损合并、无损转封装 MP4、YouTube 可恢复分块上传，以及 `/storage512` 磁盘实时监控与三级容量告警。

> **核心原则**：所有视频处理功能（合并、转封装 MP4、RTMP 推流）**严格只做 `-c copy` 无损流复制与容器重封装，绝不重新编码视频或音频**。生产部署推荐 Linux（`/storage512` 挂载点核验与 `statvfs` 容量统计基于 Linux `/proc/self/mountinfo` 与 POSIX 文件系统接口）。

---

## 1. 快速开始与单实例部署检查

> **重要提醒（防止 `409 Conflict` 与密钥泄露）**：
> 1. **严禁双实例共用同一 `BOT_TOKEN`**：切换到 Rust 版前，必须先停止并禁用旧版 Python 服务（如 `videobot.service`）及任何残留 `bot_main.py` 进程，否则 Telegram `getUpdates` 长轮询会持续报 `Conflict: terminated by other getUpdates request`。
> 2. **轮换曾暴露的旧 Token**：若历史调试或旧服务日志中曾打印过真实 Bot Token 或推流串码，请先在 [@BotFather](https://t.me/BotFather) 中轮换 Token、在直播平台重置推流密钥后再填入 `.env`。

```bash
# 0) 若机器上曾运行旧版 Python Bot，先停止并禁用，确保单实例运行
sudo systemctl stop videobot.service || true
sudo systemctl disable videobot.service || true
pgrep -af "bot_main.py|media-control-bot"

# 1) 安装 Rust（>= 1.75）与 FFmpeg（Debian / Ubuntu）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
sudo apt update && sudo apt install -y ffmpeg

# 2) 编译 Release 产物
cd /opt/media-control-bot
cargo build --release          # 产物：target/release/media-control-bot

# 3) 准备配置并收紧权限
cp .env.example .env && vim .env
chmod 600 .env

# 4)（可选）准备 YouTube OAuth2 凭证
cp /path/to/token.json ./token.json && chmod 600 ./token.json

# 5) 前台试运行验证配置与挂载自检（确认无误后 Ctrl+C 交给 systemd）
./target/release/media-control-bot
```

启动后在 Telegram 向机器人发送 `/start`，即可看到包含 `/storage512` 实时磁盘容量的主控面板。

## 2. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 生产环境推荐 Linux（完整支持 `/proc/self/mountinfo` 挂载核验、POSIX `statvfs` 与 `(dev, ino)` 文件身份复核） |
| Rust | `1.75` 或更高（`edition = "2021"`，`unsafe_code = "forbid"`） |
| FFmpeg | 需同时具备 `ffmpeg` 与 `ffprobe`，且均在服务进程的 `PATH` 中 |
| 存储挂载 | `/storage512` 应为独立挂载的真实文件系统（如 `ext4`/`xfs`）；合并与转封装的临时目录均创建在 `/storage512` 内，绝不写入系统根分区 `/tmp` |
| 网络 | 出站可访问 `api.telegram.org`、`*.googleapis.com`（YouTube 上传）及目标 RTMP 服务器 |
| 权限安全 | 仅响应 `ADMIN_ID` 指定的唯一管理员；`.env`、`token.json` 等文件权限务必设为 `600` |

## 3. 配置说明（`.env`）

程序启动时从**当前工作目录**读取 `.env`（不存在则仅读取进程环境变量），注册敏感凭据到全局脱敏器后执行严格合法性校验；校验不通过会立即报错退出。

### 3.1 基础与日志配置

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `BOT_TOKEN` | 是 | — | Telegram Bot Token（敏感，日志与错误消息中自动脱敏为 `[REDACTED]`） |
| `ADMIN_ID` | 是 | — | 唯一管理员数字 ID（非零整数）；非管理员消息与回调均静默忽略 |
| `BASE_DIR` | 否 | `/storage512/bilivego/download` | 媒体文件根目录；所有文件读写/删除均通过 `PathGuard` 强制限定在此目录内 |
| `ITEMS_PER_PAGE` | 否 | `8` | 文件选择器每页展示条目数（必须 `> 0`） |
| `FFPROBE_TIMEOUT_SECONDS` | 否 | `30` | `ffprobe` 媒体探测超时秒数（必须 `> 0`） |
| `FILE_STABLE_SECONDS` | 否 | `30` | 源文件最近修改后需等待的秒数；`0` 关闭稳定性检查 |
| `TRASH_RETENTION_DAYS` | 否 | `7` | 回收站保留天数（`1..=365`）；到期清理才释放空间 |
| `LOG_FORMAT` | 否 | `pretty` | 日志格式：仅支持 `pretty`（终端可读）或 `json`（结构化 JSON） |
| `RUST_LOG` | 否 | `media_control_bot=info,teloxide=warn,hyper=warn` | `tracing` 日志过滤规则 |

### 3.2 `/storage512` 磁盘监控与三级报警配置

报警触发阈值已固化为：**一级 `>90%`**、**二级 `>95%`**、**三级 `>98%`**（基于未四舍五入浮点使用率 `used / (used + avail) * 100.0` 严格大于比较）。

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `STORAGE_MOUNT_POINT` | 否 | `/storage512` | 待监控与核验的目标挂载点路径 |
| `DISK_CHECK_INTERVAL_SECS` | 否 | `300` | 后台定时巡检间隔秒数（默认 5 分钟；**待用户确认**） |
| `DISK_ALERT_RESET_L1` | 否 | `85.0` | 一级报警（`>90%`）滞后回落复位百分比，取值 `(0.0, 90.0]`（**待用户确认**） |
| `DISK_ALERT_RESET_L2` | 否 | `90.0` | 二级报警（`>95%`）滞后回落复位百分比，取值 `(0.0, 95.0]`（**待用户确认**） |
| `DISK_ALERT_RESET_L3` | 否 | `95.0` | 三级报警（`>98%`）滞后回落复位百分比，取值 `(0.0, 98.0]`（**待用户确认**） |
| `DISK_ALERT_STATE_FILE` | 否 | `./.disk_alert_state.json` | 跨重启报警去重状态文件（仅保存级别与挂载异常闩锁，不含敏感信息） |

### 3.3 RTMP 无损推流配置

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `RTMP_URL` | 否 | 空 | 完整 RTMP 推流地址（如 `rtmp://host/app/stream_key`）；日志中自动脱敏为 `rtmp://host/[REDACTED]` |
| `RTMP_RW_TIMEOUT_SECS` | 否 | `30` | RTMP 网络读写超时秒数（映射为 FFmpeg `-rw_timeout` 微秒；**待用户确认**） |
| `RTMP_WARN_BITRATE_MBPS` | 否 | `0.0` | 源片总码率上行风险提示阈值（Mbps）；默认 `0.0` 表示仅展示探测码率而不弹风险提示（**待用户确认**） |

### 3.4 YouTube 可恢复分块上传配置

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `TOKEN_FILE` | 否 | `./token.json` | YouTube OAuth2 `authorized_user` 凭证路径 |
| `YOUTUBE_MAX_CONCURRENT_UPLOADS` | 否 | `2` | 最大并发上传数（必须 `> 0`；**低配 VPS 建议在 `.env` 显式设为 `1`**） |
| `YOUTUBE_MAX_QUEUE_SIZE` | 否 | `10` | 除并发运行任务外允许额外排队等待的最大任务数（必须 `> 0`；**待用户确认**） |
| `YOUTUBE_UPLOAD_CHUNK_MB` | 否 | `10` | **真实生效**的单次 HTTP `PUT` 可恢复上传分块大小（MB，取值 `1..=64`，恒满足 `256 KiB` 整数倍；内存流式读取每次仅占用约 `64 KiB` 缓冲） |
| `YOUTUBE_RECOVERY_MODE` | 否 | `none` | 服务重启后的队列恢复策略（**待用户确认**，保守默认 `none`）：<br>• `none`：重启后不自动恢复上传<br>• `requeue`：重启后先核验既有会话是否已完成，未完成则重新排队上传<br>• `resume`：持久化会话 URI 与文件身份（`0600` 权限），重启后通过 `308 Range` 断点续传 |
| `YOUTUBE_UPLOAD_QUEUE_FILE` | 否 | `./youtube_upload_queue.json` | 当 `YOUTUBE_RECOVERY_MODE` 为 `requeue` 或 `resume` 时使用的持久化文件路径 |

### 3.5 视频无损合并配置

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `MERGE_MIN_DURATION_RATIO` | 否 | `0.95` | 合并结果保留时长最低比例（相对输入总时长，取值 `0.0..=1.0`） |
| `MERGE_MIN_SIZE_RATIO` | 否 | `0.80` | 合并结果体积辅助比对阈值（取值 `0.0..=1.0`；仅作诊断辅助提示，不单独否决有效无损合并） |
| `MERGE_MAX_LOSS_SECONDS` | 否 | `3` | Stage 2C 有界片尾无损截除最大探测秒数（取值 `0..=60`；**待用户确认**） |
| `MERGE_ALLOW_AUTO_TRIM` | 否 | `false` | 是否允许 Stage 2C 自动产出截除片尾损坏尾包后的合并成片（**待用户确认**；保守默认 `false`：仅在临时目录探测可行秒数并向用户报告，随后清理临时文件，不自动丢弃任何内容） |

## 4. YouTube 凭证（`token.json`）

上传使用 OAuth2 的 `authorized_user` 凭证，所需 scope 为 `https://www.googleapis.com/auth/youtube.upload`。文件内容形如：

```json
{
  "client_id": "your_client_id.apps.googleusercontent.com",
  "client_secret": "your_client_secret",
  "refresh_token": "your_refresh_token",
  "token_uri": "https://oauth2.googleapis.com/token",
  "scopes": ["https://www.googleapis.com/auth/youtube.upload"],
  "type": "authorized_user"
}
```

请确保文件权限为 `chmod 600 token.json`。上传固定使用 **私享（`private`）** 隐私级别、分类 `22`（People & Blogs），标题取清洗后的文件名（移除控制字符并按字符边界截断至安全长度）。仅当 YouTube 服务端返回 HTTP `200`/`201` 且响应体包含有效 `id`（`video_id`）时，Bot 才报告上传完成并附上观看链接与 YouTube Studio 链接。

## 5. 后台运行（systemd）与优雅停机

`/etc/systemd/system/media-control-bot.service` 示例：

```ini
[Unit]
Description=VPS Media Control Bot (Rust)
After=network-online.target local-fs.target
Wants=network-online.target

[Service]
Type=simple
User=media
WorkingDirectory=/opt/media-control-bot
ExecStart=/opt/media-control-bot/target/release/media-control-bot
Environment=RUST_LOG=media_control_bot=info,teloxide=warn,hyper=warn
Environment=PATH=/usr/local/bin:/usr/bin:/bin
Restart=on-failure
RestartSec=5
TimeoutStopSec=15

[Install]
WantedBy=multi-user.target
```

常用运维命令：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now media-control-bot
sudo systemctl status media-control-bot
sudo journalctl -u media-control-bot -f
```

**信号与优雅停机说明**：

- 程序同时监听 **`SIGINT`（Ctrl+C）** 与 **Unix `SIGTERM`（`systemctl stop` 默认信号）**。
- 收到停机信号后，主程序会先停止后台磁盘巡检，并调用任务协调器向正在运行的独占任务（FFmpeg 子进程）和所有运行中/排队中的 YouTube 上传任务广播取消信号，最多等待 5 秒完成子进程回收与临时目录清理后再退出；同时所有 FFmpeg/FFprobe 子进程均启用了 `kill_on_drop(true)` 兜底。

## 6. 命令与功能说明

| 命令 | 作用 |
| --- | --- |
| `/start` | 实时采样 `/storage512` 磁盘状态并展示主控面板（根目录、磁盘容量行、独占任务、上传/排队统计） |
| `/stop` | 终止当前独占任务，并立即取消所有运行中及排队等待信号量的 YouTube 上传任务 |
| `/uploads` | 查看 YouTube 上传任务列表（区分服务端已确认进度与本地已发送进度、当前状态、耗时） |
| `/tasks` | 查看当前任务并选择单独停止某一个任务 |
| `/history` | 查看本次运行的最近 20 条任务结果（重启后清空） |
| `/pending` | 查询状态待核实的 YouTube 会话；核实按钮只查询、不重新发送视频。需先配置 `YOUTUBE_RECOVERY_MODE=requeue` 或 `resume` 以保存会话记录；“继续原会话”会发送尚未确认的剩余数据 |
| `/trash` | 查看同盘回收站并恢复未到期文件 |
| `/find 关键词` | 在当前目录按文件名筛选；选择模式支持一次选中本页文件 |
| `/clearfilter` | 清除文件名筛选 |

### 6.1 主菜单 `/storage512` 磁盘显示与三级报警

- **实时展示位置**：位于主菜单 `根目录` 与 `提示` 之间：
  - 正常时：`💽 /storage512：已用 431G / 总量 503G（91%），可用 48G`
  - 挂载异常或读取失败时：`💽 /storage512：磁盘信息暂不可用`（面板其余功能不受阻塞）
- **实时触发时机**：每次发送 `/start`、每次点击「🔙 返回主菜单」、程序启动自检、后台每 `DISK_CHECK_INTERVAL_SECS` 秒定时巡检。
- **三级主动报警**：
  - **一级警告（`>90%`）**：提醒关注录播增长并规划清理或归档；
  - **二级严重告警（`>95%`）**：警告剩余空间紧张，合并等需要临时空间的任务可能受限；
  - **三级紧急告警（`>98%`）**：警告即将写满，建议立即停止新写入并清理空间。
- **去重与复位机制**：若容量从正常直接跃升至 `>98%`，单次巡检只发送一条最高级别（三级）告警；仅在 Telegram 消息**实际发送成功**后才置位已通知状态（发送失败下次巡检自动重试）；当使用率回落至对应复位阈值（默认 `<=85%` / `<=90%` / `<=95%`）后自动解除对应级别闩锁。若 `/storage512` 未独立挂载（如退化到 `/` 或 `tmpfs`），会独立发送挂载异常告警且不污染容量级别状态。

### 6.2 浏览远程文件

- 单选模式，点击文件通过 `ffprobe` 展示文件名、大小、时长、视频/音频编码与修改时间；目录列表仅展示 `.mp4`、`.mkv`、`.flv`、`.ts` 文件，自动隐藏 `.mcb_tmp_*` 临时工作目录与隐藏文件。
- 所有列表回调均受 `MenuSnapshot` 保护：若旧消息已过期或底层目录发生文件增删改名，Bot 会提示目录已变化并自动刷新当前列表，绝不按错位序号操作错误文件。

### 6.3 RTMP 单路无损推流

- 推流前先用 `ffprobe` 校验视频流存在性及 FLV/RTMP 常见封装兼容性（若检测到無视频流将直接拦截；对 HEVC/AV1 等依赖平台 Enhanced-RTMP 支持的编码会给出兼容性提示，仍坚持 `-c copy` 不重编码）。
- 命令显式指定 `-re -i <file> -map 0:v:0 [-map 0:a:0 | -an] -c copy -rw_timeout <us> -f flv <rtmp_url>`。
- 若源文件时长未知（如未正常封尾的 `.flv`/`.ts`），自动降级展示「已推流时长 + 实时倍速/码率」，不会报错或卡死在 `0%`。
- FFmpeg 退出码为 `0` 时仅表述为「本地文件已发送完毕」，不虚报远端直播间画面状态。

### 6.4 YouTube 可恢复分块上传

- 多选模式按用户点击顺序依次入队；当「运行中 + 排队中」达到上限时明确提示拒绝入队。
- 排队等待 `Semaphore` 期间收到 `/stop` 会通过 `tokio::select!` 立即退出并清理任务，无需苦等前序大文件传完。
- 上传期间每个分块读取后都会复核源文件身份（大小、修改时间、Unix `(dev, ino)`），若源文件在上传途中被覆盖或截断会立即中止，防止上传拼接损坏的数据。

### 6.5 多阶段无损视频合并

- **严格按用户点击顺序合并**：你在界面上依次点击的第 1、2、3 个分段即为最终合并顺序，列表会显示 `✅1.`、`✅2.` 序号。
- **合并前预检**：核验所有分段视频编码/分辨率/帧率一致性，并核算 `/storage512` 可用空间是否足以容纳中间产物 + 输出临时文件 + `512 MiB` 安全余量。
- **多阶段无损策略（零重编码）**：
  1. **Stage 1**：极速直连 `concat` demuxer（`-c copy -movflags +faststart`）；
  2. **Stage 2A**：逐段标准无损封装 `.ts`（H.264/HEVC 自动附加 `h264_mp4toannexb` / `hevc_mp4toannexb` bitstream filter）后拼接输出 MP4；
  3. **Stage 2B**：若录播断流导致时间戳跳变或损坏包，启用 `-fflags +discardcorrupt+genpts` 重新无损封装 `.ts` 后拼接；
  4. **Stage 2C（受控片尾无损截除）**：针对分段末尾几秒损坏导致整段失败的场景，在 `1..=MERGE_MAX_LOSS_SECONDS` 秒范围内用 `-t <keep>` + `-c copy` 探测最小截除秒数。默认 `MERGE_ALLOW_AUTO_TRIM=false` 下**不会自动产出截除文件**，而是清理临时目录后报告具体分段与所需截除秒数，由管理员确认决定。
- **严格成片校验与原子发布**：所有阶段均强制要求退出码为 `0`、文件非空、`ffprobe` 探测流与有效时长成功（`ffprobe` 失败绝不跳过校验）、保留时长达标；全部通过后才通过硬链接原子发布到目标文件名（绝不使用 `-y` 覆盖已有文件）。

### 6.6 无损转封装 MP4

- 多选模式，逐个执行无损容器重封装（`-map 0:v:0` + 可选音频流 + `-c copy -movflags +faststart`），先写入同目录隐藏临时文件并通过 `ffprobe` 校验后再原子硬链接发布，失败自动清理临时文件，源文件完好保留。

### 6.7 批量移入回收站

- 多选确认后生成一次性确认令牌 `token` 并记录每个待删文件的身份快照（路径、大小、修改时间、Unix `(dev, ino)`）。
- 点击确认时逐文件复核身份，随后移入媒体盘内的隐藏回收站。`/trash` 可恢复原路径仍空闲的文件；超过 `TRASH_RETENTION_DAYS` 后后台清理。移入回收站不会立即释放磁盘空间。

## 7. 常见问题排查

| 现象 | 原因与处理 |
