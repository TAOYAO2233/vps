# xboard 审计机器人使用向导

## 准备

在 Ubuntu 20.04+ 主控机确认 `xboard-node` 正以 systemd 服务运行，准备 Telegram Bot Token 与接收者 Chat ID。安装脚本需要 root 权限、网络连接、Python 3、systemd 和 rsyslog。先备份 rsyslog、xboard-node 配置及同名 systemd 服务。

## 交互安装

```bash
cd vps-telegram-bot/xboard_audit_bot
sudo bash xboard_audit.sh
```

在主控机选“设置本机为主控”，输入 Token 和以逗号分隔的 Chat ID。脚本会将 `journalctl -u xboard-node` 导入 `/home/xboard_log/xboard.log`，配置 rsyslog UDP 接收，按 Python 版本下载对应审计源码，创建虚拟环境和 `xboard-audit` 服务。

**安装后必须检查 `/root/xboard_log/xboard_monitor.py` 的 `TG_CHAT_IDS`。**当前安装脚本以单行 `sed` 模式替换接收者列表，但仓库源码使用多行列表，替换可能没有生效。若仍是示例 ID，请手动改成自己的 Chat ID，再重启服务。也请确认 `TG_BOT_TOKEN` 已正确写入。

在每台客户端运行同一脚本并选客户端选项，输入主控机公网 IP 与节点标识。主控机增加新节点后，还需按菜单更新监控列表。脚本默认使用 514/UDP；公网部署须限制允许发送的源 IP。操作细节与手动配置参考[多机日志指南](多台vps日志推送.md)。

## 验证与维护

```bash
sudo systemctl status xboard-tunnel xboard-audit rsyslog
sudo journalctl -u xboard-audit -f
sudo tail -f /home/xboard_log/xboard.log
```

确认客户端日志到达主控机后，再检查 Telegram 是否收到汇总消息。修改 `/root/xboard_log/xboard_monitor.py` 中的 `TG_BOT_TOKEN`、`TG_CHAT_IDS`、`LOG_TASKS` 或 `PUSH_INTERVAL` 后运行 `sudo systemctl restart xboard-audit`。

若服务启动失败，先检查部署目录中的实际文件名与 `ExecStart` 是否一致，再看 `journalctl -u xboard-audit -e`。仓库里的 [`xboard-audit.service`](xboard-audit.service) 是手动部署示例；脚本生成的服务文件可能使用另一入口文件名，以已安装服务为准。
